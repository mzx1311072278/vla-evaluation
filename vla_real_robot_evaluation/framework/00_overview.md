# VLA 真机评测框架总览

## 1. 目标与边界

本框架用于比较 VLA 模型/版本在真实机器人上的任务能力、泛化、鲁棒性、安全性、效率、控制质量和系统性能。它面向固定机械臂操作任务，同时允许扩展到双臂与移动操作。

本框架不是机器人安全认证方案，也不以一个总分替代工程判断。安全、数据有效性和可追溯性采用非补偿式门禁；通过门禁后，再比较统计指标。

## 2. 三种落地方式

| 方式 | 做法 | 优点 | 局限 | 适用阶段 |
|---|---|---|---|---|
| A. 报告脚本增量扩展 | 在现有 Genie02 CSV/JSON/Markdown 工具上增加字段和指标 | 成本最低、最快可用 | 数据模型容易继续受单任务约束，在线事件与版本追踪较弱 | 近期补测、单机器人验证 |
| B. 模块化评测流水线（推荐） | 建立 registry、campaign/session/trial/event schema、采集适配层、指标插件、报告与门禁 | 可复用现有读取器；支持多模型、多任务和统计比较；边界清晰 | 需要先统一数据契约与 SOP | 正式评测系统第一版 |
| C. 完整在线评测平台 | 在 B 之上加入 Web UI、调度、实时监控、审批、资产管理和集群推理 | 自动化程度高、适合规模化运营 | 建设成本和维护成本高，容易在口径未稳定前固化错误设计 | 多团队、多机器人常态化评测 |

建议先实施 B；保留现有 Genie02 读取和报告能力作为适配器，待 schema 和门禁经过数轮真机验证后再建设 C。

## 3. 六层对象模型

```text
Campaign（一次冻结的模型比较/发版评测）
└── Scenario（任务、场景与扰动条件）
    └── Session（同一机器人配置下的连续执行批次）
        └── Trial（一次独立复位的统计试验）
            └── Episode（策略实际控制时序）
                ├── Time series（观测、状态、策略动作、执行动作、时延）
                ├── Events（碰撞、接管、超限、恢复、E-stop）
                ├── Artifacts（多视角视频、日志、配置、模型清单）
                └── Annotations（成功、子目标、失败模式、复核结论）
```

统计独立单元默认是 trial，不是视频帧。帧数再多也不能替代独立重置后的重复试验。

## 4. 评测维度

| 维度 | 核心问题 | 代表输出 |
|---|---|---|
| 任务能力 | 是否完成用户要求 | 严格成功率、子目标完成率、失败阶段 |
| 泛化 | 训练分布变化后还能否完成 | 按空间、物体、背景、指令、组合 OOD 分层成功率 |
| 鲁棒性 | 受到受控扰动后能否继续/恢复 | 扰动层 Full SR、恢复状态率、恢复时间、性能降幅 |
| 安全 | 是否避免危险并正确停止 | 碰撞/超限/近碰、接管、E-stop、safe-stop 事件 |
| 效率 | 完成任务付出多少时间与动作 | 成功 TTS、截尾耗时、路径/动作长度、吞吐 |
| 控制质量 | 动作是否稳定、准确且可执行 | 末端误差、jerk、抖振、抓取滑移、峰值力/冲击 |
| 系统性能 | 部署链路是否实时、稳定 | 端到端延迟 p50/p95/p99、deadline miss、动作陈旧度 |
| 指令遵循 | 是否做对对象、位置、顺序和约束 | 属性/关系/否定/顺序条件满足率 |
| 可追溯性 | 结果能否复现和审计 | 模型/代码/配置/标定/场景/原始证据完整率 |

## 5. 测试分层

正式层级前先执行 **Preflight 数据与安全检查**：时间同步、相机/力传感器、限位、watchdog、E-stop、配置哈希和日志完整性。Preflight 是每个 session 的 SOP 阶段，不占用测试层级编号。

1. **L0 冒烟测试**：少量已知简单任务，检查部署链路、动作方向和基本能力；只用于快速阻断。
2. **L1 ID 基线**：训练/开发分布内的标准任务，用于稳定性、回归和上限评估。
3. **L2a--L2d 单轴泛化、L2e 组合 OOD**：分别改变空间、物体、背景/场景、指令，再组合两个及以上未见因素。
4. **L3 鲁棒与恢复**：在预先定义的安全范围内施加遮挡、物体位移、执行失败或环境变化；扰动层 Full SR 使用全部 valid 分配 trial，恢复状态率使用协议定义的 eligible 子集。
5. **L4 长程任务**：按子目标和阶段记录进度、恢复、停滞和最终完成；避免只报最终二元标签。
6. **L5 跨机器人/场地**（可选）：当模型声明 embodiment 或跨场地泛化能力时启用。

## 6. Trial 终态口径

每个 trial 先判定“是否有效”，再判定自主结果；两者不能混为一列。

| 字段 | 推荐枚举 | 口径 |
|---|---|---|
| `validity` | `valid`, `invalid_setup`, `invalid_logging`, `invalid_external` | 只有预先定义的非模型原因才能排除分母；必须保留原始记录和原因 |
| `autonomy_outcome` | `success`, `partial`, `failure`, `timeout`, `safety_stop`, `human_takeover`, `not_evaluable` | `safety_stop` 和 `human_takeover` 不能按无效试验重跑并删除；无效 trial 使用 `not_evaluable` |
| `safety_outcome` | `no_event`, `near_miss`, `limit_stop`, `collision`, `estop` | 按 safety profile 的严重度优先级保存最严重摘要；全部事件保留在 event 流 |
| `failure_stage` | 场景定义的阶段 ID | 用于长程任务定位能力瓶颈 |

人工接管的任务自主结果记为失败/接管，同时可把“安全人员成功避免伤害”记录为安全层的独立事实。

## 7. 比较原则

- 比较前冻结模型、权重、代码、容器、提示词、动作后处理、安全配置和场景清单。
- 模型使用相同的初始条件集合；条件顺序随机化或交错执行，减小设备热态、光照和操作员学习效应。
- 预先指定主要指标、分母、无效试验规则、超时和停止规则，不在看到结果后改口径。
- 成功率同时报告 `k/n`、点估计和区间；按任务/扰动分层报告，并给宏平均，避免高频简单任务主导总分。
- 对连续指标给出样本量、中位数/分位数或均值/标准差，并说明只在成功 trial 上统计还是全体统计。
- 模型比较优先使用配对场景/初始条件；报告差值和不确定性，而不仅是两个独立百分比。
- 视频判定尽量盲化模型版本；模糊样本采用双人复核并保留分歧。

## 8. 非补偿式发版门禁

门禁顺序如下：

1. **数据门禁**：必需日志、视频、版本、时钟同步和标注完整；不通过则结果不可发布。
2. **安全硬门禁**：出现预定义的严重碰撞、越界、保护失效或不可控行为时直接阻断；不能用成功率抵消。
3. **能力硬门禁**：关键任务/关键场景不得低于预先冻结的底线；阈值由风险和现有基线确定。
4. **统计门禁**：候选模型相对基线的退化幅度、置信边界或非劣界满足预设标准。
5. **观察项**：效率、轨迹质量、资源与次要泛化指标用于排序和持续优化，不替代硬门禁。

框架不提供跨项目统一数值阈值。具体阈值必须由任务风险、机器人能力、当前生产基线和样本预算共同确定，并在执行前冻结。
