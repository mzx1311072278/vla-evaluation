# VLA 单机自动评测网站设计

## 1. 目标

将现有 Genie02 评测脚本封装成组内可复用的内部网站。安装 Ubuntu 22.04 LTS 的 4090 台式机是唯一评测服务器，同时保存评测代码、模型、原始推理数据、运行结果和报告，并承担 CPU 与 GPU 计算。

组员不需要登录 SSH、配置 Python/CUDA 环境或执行命令。标准操作只有：

1. 从已登记的云服务器或局域网机器拉取数据，或将数据推送到服务器约定目录。
2. 打开网站，选择数据集和评测方案。
3. 点击开始，等待并查看报告。

## 2. 第一版范围

第一版包含：

- 扫描服务器白名单目录并发现 LeRobot 数据集或 Genie02 Session。
- 从管理员登记的云服务器或局域网数据源，通过 SSH/SFTP/rsync 将数据断点拉取到 4090。
- 展示导入进度、传输速度、校验状态和失败重试入口。
- 展示数据集名称、路径、大小、Episode 数、更新时间和预检状态。
- 选择 Genie02 评测方案并提交任务。
- 运行现有 GSR、TTS、平滑度和 Markdown 报告链路。
- 可选运行本地 VLM 视频分析，识别成功前失败尝试次数并标记人工复核项。
- 展示任务排队、运行阶段、日志摘要、错误原因和重试入口。
- 保存历史任务，并导出 Markdown、CSV 和 JSON 结果。
- 固定数据指纹、评测配置、代码版本、模型版本和 Prompt 版本，保证结果可追溯。

第一版不包含：

- 云端服务器或跨机器分布式计算。
- 机器人在线控制和实时采集。
- 复杂审批、发布门禁和多组织权限。
- 浏览器上传数十 GB 视频。
- 普通用户登记任意远程主机、端口或远程根目录。
- 任意脚本上传或任意服务器命令执行。
- 自动删除原始数据。

## 3. 产品形态

产品主体是一个仅在公司内网或 VPN 中开放的网站。交互式 SSH 只供管理员部署、更新和排障，普通组员通过网页发起远程拉取，不登录服务器 shell。

网站包含五个主要页面：

1. **数据导入**：选择已登记的数据源和远程目录，查看拉取进度与校验结果。
2. **数据集**：显示服务器已发现的数据集和预检状态。
3. **新建评测**：选择数据集、评测方案和是否启用 VLM。
4. **任务详情**：显示队列位置、当前阶段、耗时、日志和失败重试。
5. **报告**：显示核心指标、Episode 明细、失败证据、人工复核项和导出入口。

第一版的白名单数据目录、模型路径和并发数由管理员通过服务器配置文件维护，不增加网页设置页。

## 4. 单机架构

```text
组员浏览器
    |
    v
内网反向代理（Caddy）
    |
    v
FastAPI Web 应用
    |-- 数据集扫描与预检
    |-- 远程数据源与导入任务
    |-- 任务和报告 API
    |-- 服务端页面
    |-- SQLite 元数据
    |
    v
Redis + RQ 任务队列
    |-- 数据导入队列 -> Transfer Worker（并发数 1）
    `-- 评测队列     -> Evaluation Worker（并发数 1）
                           |-- Genie02 普通指标插件
                           |-- 本地 VLM 插件
                           `-- 报告生成插件
    |
    v
服务器本地磁盘
    |-- 原始数据
    |-- 本地 VLM 权重
    |-- 运行产物和报告
    `-- 日志与数据库
```

第一版将评测 Worker 并发固定为 1，避免 4090 显存竞争。数据导入使用独立的单并发 Transfer Worker，因此一次远程传输可以与一次评测并行；额外导入和评测任务分别排队。网页关闭不会影响运行。

前端采用 FastAPI + Jinja2 + HTMX 的服务端页面，避免第一版同时维护独立 React/Vue 工程。若后续交互复杂度明显增加，可以保留 API 并替换前端，不改变评测插件。

## 5. 服务器目录

默认目录建议如下，实际根目录可通过配置修改：

```text
/srv/vla-eval/
|-- app/                         # 网站与评测代码
|-- config/
|   |-- app.yaml                 # 目录、并发、保留策略
|   `-- profiles/                # 评测方案 YAML
|-- data/
|   |-- inbox/<user>/<dataset>/  # 组员传入的原始数据
|   |-- staging/<import_id>/     # 未完成的远程导入
|   |-- models/                  # 本地 VLM 权重
|   |-- runs/<job_id>/           # 每次任务的中间产物与报告
|   `-- db/app.sqlite3           # 元数据数据库
`-- logs/
```

数据可以通过两类方式进入 `inbox`：4090 主动从已登记的远程数据源拉取，或者组员通过 SMB、SFTP、rsync 推送。Windows 和 macOS 可以直接挂载 SMB；自动化同步优先使用 rsync over SSH。网站只允许浏览配置中的白名单根目录，不接受用户输入的任意本地绝对路径。JSON、YAML 和 CSV 等小型补充文件可以通过网页上传到选定数据集的附件目录。

为避免扫描到未传完的数据，数据目录只有在满足以下任一条件时才标记为可评测：

- 上传工具完成后将临时目录原子重命名为最终数据集目录；或
- 用户在网页点击“重新检查”，完整预检通过后显式注册。

## 6. 远程数据导入

管理员通过配置文件登记 `RemoteSource`，每个数据源包含：

- 显示名称、主机名或 IP、SSH 端口，默认端口为 `22`。
- 协议，第一版优先使用 rsync over SSH，SFTP 作为兼容方案。
- 只读 SSH 用户、私钥引用和固定的服务器 Host Key。
- 一个或多个允许拉取的远程根目录。

普通组员在网页只能选择已登记的数据源，并填写或浏览白名单根目录下的相对路径。网页不能提交任意主机、端口、用户名、私钥、绝对根目录或 rsync 参数。

导入流程如下：

```text
QUEUED
  -> CONNECTING
  -> TRANSFERRING
  -> VERIFYING
  -> PREFLIGHT
  -> READY
```

传输内容先写入 `staging/<import_id>/`。rsync 使用部分文件和断点续传；传输完成后校验文件清单和大小，再执行数据格式预检。全部通过后原子移动到 `inbox/<user>/<dataset>/`，只有 `READY` 数据集可以提交评测。失败任务进入 `FAILED`，可从已有部分文件继续重试。

如果远程机器位于云端，4090 必须能通过公司 VPN、专线或受控公网出口访问其 SSH 端口。远程账号只授予数据根目录读取权限：rsync 数据源使用受限的只读 rsync 命令包装器，SFTP 数据源禁用交互式 shell；两者都禁止源端写入和删除。

## 7. 数据集发现与预检

扫描器只识别已注册的数据格式适配器。第一版包含：

- Genie02 Session：`session.json`、`episodes.csv` 和相关轨迹引用。
- LeRobot：`meta/info.json`、`meta/episodes/`、`data/`，视频为 VLM 启用时的条件输入。

预检至少验证：

- 必需文件存在且可读。
- Parquet、JSON、CSV 可以解析。
- Episode 索引唯一且引用文件存在。
- 视频引用和时间窗口有效。
- 磁盘剩余空间满足运行产物预算。
- 数据目录在白名单根目录内，解析符号链接后仍不越界。

预检失败时禁止提交任务，并给出面向用户的修复提示，不显示 Python 堆栈作为主要错误信息。

## 8. 评测插件边界

评测主流程不直接依赖某个具体模型或数据格式。插件通过稳定接口协作：

- `DatasetAdapter`：发现数据集、读取元数据、生成数据指纹并执行预检。
- `MetricPlugin`：根据数据集和运行目录生成结构化指标与中间文件。
- `VLMPlugin`：从视频抽帧并输出符合固定 Schema 的语义分析结果。
- `ReportPlugin`：读取结构化结果，生成网页数据和导出文件。

现有 `genie02_eval_report.py` 作为第一批 `MetricPlugin` 和 `ReportPlugin` 的实现基础；`attempt_eval` 作为第一批 `VLMPlugin` 的实现基础。原有计算函数应被直接调用，不通过拼接 shell 命令调用。

每个评测方案是版本化 YAML，定义启用的适配器和插件、参数默认值、输出要求及 VLM 开关。新增任务或指标时增加插件和方案，不修改 Web 路由。

## 9. VLM 的职责

VLM 是可选的视频智能分析插件，不是基础指标的唯一裁判。第一版复用现有本地 Qwen VLM 方案，默认使用服务器本地权重。

VLM 负责：

- 对 Episode 视频进行全局和局部密集抽帧。
- 识别最终成功前的失败尝试次数。
- 输出尝试时间、最终成功时间、置信度、原因和证据帧。
- 按阈值标记需要人工复核的 Episode。

VLM 不负责替代确定性的轨迹指标，也不应在没有人工验证的情况下覆盖原始成功标签。模型权重、Prompt、抽帧参数、推理参数和输出 Schema 必须保存到任务快照中。

4090 的 VLM 任务并发固定为 1。第一版优先复用当前 `Qwen2.5-VL-3B-Instruct`，待建立人工标注验证集后再评估是否切换 7B 或其他模型。

## 10. 任务状态与执行流

任务状态如下：

```text
QUEUED
  -> PREFLIGHT
  -> METRICS
  -> VLM            # 未启用时跳过
  -> REPORT
  -> SUCCEEDED
```

任意运行阶段可以进入 `FAILED`，排队中的任务可以进入 `CANCELLED`。第一版不强行中断已进入 CUDA 推理的进程；取消请求会在安全检查点生效。

提交任务时保存：

- 数据集 ID、绝对路径和内容指纹。
- 评测方案名称、版本和完整参数快照。
- 代码版本或构建版本。
- VLM 权重路径、权重标识、Prompt 和推理参数。
- 提交人、提交时间和任务 ID。

相同数据指纹、相同方案版本和相同参数形成运行键。已有成功结果时网页提示复用或明确创建新运行，避免误点造成重复 GPU 计算。

## 11. 错误处理与恢复

- 每个阶段写入独立日志和阶段结果，成功阶段不因后续失败而丢失。
- 远程导入失败时保留 `staging` 中的部分文件，重试只传缺失或变化的数据。
- 远程 Host Key、凭据或白名单校验失败时立即停止，不自动绕过安全检查。
- 用户可从失败阶段重试；重试前重新验证数据指纹，数据变化时必须创建新任务。
- VLM 单个 Episode 失败时记录错误并继续处理其他 Episode，最终任务可以成功但带告警。
- CUDA 显存不足、模型加载失败和磁盘空间不足使用明确错误码与处理建议。
- Worker 重启后，排队任务保留；中断的运行任务标记为待恢复，由管理员或用户确认重试。
- 报告明确区分完整成功、成功但有告警、失败和取消。

## 12. 安全与运维

- 网站只绑定内网地址，通过公司 VPN 或内网访问，不直接暴露到公网。
- Caddy 提供统一内网入口。FastAPI 应用使用本地账号登录，每名组员一个账号，密码只保存强哈希，登录状态使用带过期时间的安全会话 Cookie。
- 网页入口只开放 Caddy 的 `443`。管理 SSH 使用 `22`；如启用外部推送，则在 `22` 上配置无 shell 的 SFTP/受限 rsync 账号。`445` 只在内网启用 SMB 时开放。FastAPI、Redis 和 Worker 端口不对外暴露。
- 主动拉取数据时，由 4090 发起到已登记数据源 SSH 端口的出站连接，通常是 `22`；这不需要为拉取功能额外开放一个入站端口。
- 交互式 SSH 只供管理员使用；数据推送账号只能执行受限文件传输，不能获得 shell。
- 所有数据路径必须位于白名单根目录；禁止网页提交任意命令。
- 服务使用非 root 用户运行，数据目录和模型目录按最小权限授权。
- 台式机关闭自动睡眠，服务开机自启，任务和数据库使用持久卷。
- 设置磁盘容量告警。自动清理只针对可再生缓存和抽帧；原始数据及正式报告不自动删除。
- 数据库与配置每日备份到独立磁盘或公司现有备份位置。

## 13. 部署方式

服务器操作系统固定为 Ubuntu 22.04 LTS，不维护 Windows 原生或 WSL2 部署分支。宿主机安装稳定版 NVIDIA 驱动、Docker Engine、Docker Compose Plugin 和 NVIDIA Container Toolkit；CUDA/PyTorch 用户态依赖由 Evaluation Worker 镜像固定。Ubuntu 22.04 的标准安全维护到 2027 年 4 月，届时应升级到后续 LTS 或启用 Ubuntu Pro 扩展安全维护。

使用 Docker Compose 管理以下服务：

- `proxy`：Caddy。
- `web`：FastAPI 网站。
- `transfer-worker`：只负责 rsync/SFTP 数据导入，不使用 GPU。
- `evaluation-worker`：安装 CPU/GPU 依赖并运行评测流水线。
- `redis`：持久任务队列。

Evaluation Worker 通过 NVIDIA Container Toolkit 使用 4090。模型权重、原始数据、运行结果和 SQLite 数据库使用宿主机目录挂载，不写入容器镜像。

Web、Transfer Worker 和 Evaluation Worker 使用各自的镜像，避免让 Web/传输服务携带 CUDA 依赖；第一版仍保持单仓库和一条 Docker Compose 启动命令。

## 14. 测试与验收

自动化测试包括：

- 数据适配器和路径白名单单元测试。
- 远程数据源白名单、Host Key 固定、相对路径越界和命令参数注入测试。
- 断点续传、网络中断恢复、部分文件校验和导入原子发布集成测试。
- Genie02 指标插件回归测试，使用现有样例比对 CSV、JSON 和核心指标。
- VLM 输出 Schema、错误降级和人工复核策略测试；单元测试使用模拟模型响应。
- 任务状态、重试、取消和 Worker 重启集成测试。
- 从“远程导入数据”到“生成报告”的浏览器端到端测试。
- Docker Compose 启动、健康检查、GPU 可见性和持久化冒烟测试。

第一版验收标准：

1. 新组员无需 SSH，在浏览器中完成一次已有数据集评测。
2. 组员可以从一台已登记的局域网或云端机器拉取数据，网络中断后继续传输，不需要重新开始。
3. 网页关闭后导入和评测任务继续，重新打开可以恢复进度展示。
4. 现有 Genie02 样例的核心指标与当前脚本输出一致。
5. 启用 VLM 时能够在 4090 上完成样例任务，并输出结构化结果和人工复核标记。
6. 输入缺失、传输中断、凭据错误、显存不足、磁盘不足和 Worker 重启都有可理解的状态与恢复路径。
7. 同一任务的报告可以追溯到数据指纹、方案、代码和模型版本。

## 15. 分阶段落地

### 阶段一：可用闭环

- 整理现有评测函数接口。
- 建立远程数据源配置、数据导入页面和断点续传 Worker。
- 建立数据集扫描、预检和评测方案。
- 实现数据导入与评测两条持久队列、两个单并发 Worker、进度和日志。
- 接入现有 Genie02 指标、VLM 和报告。
- 提供数据导入、数据集、新建评测、任务详情和报告五个页面。
- 用 Docker Compose 部署到 4090 台式机。

### 阶段二：组内稳定使用

- 完善账号、磁盘告警、备份、报告对比和人工复核台。
- 建立小规模人工标注集，量化本地 VLM 的准确率和一致性。
- 增加新数据适配器、指标插件和评测方案。

### 阶段三：规模增长后再评估

- 只有当单台 4090 的排队时间、存储或可用性成为实际瓶颈时，才考虑 PostgreSQL、独立存储或增加 Worker。
- 第一版接口保留扩展边界，但不提前建设分布式平台。
