# 数据集与评测任务列表管理设计

## 1. 目标

在不删除数据集文件、评测输出或历史报告的前提下，为数据集列表和评测任务列表增加持久化归档、恢复、关键词包含搜索和稳定排序。默认列表隐藏归档内容；用户可以通过“显示已归档”开关查看并恢复归档记录。

本功能继续在 `feature/vla-eval-web-vlm-api-backend` 分支实施，`main` 不修改，无关的 `uv.lock` 不纳入提交。

## 2. 现状与约束

- 数据集列表当前固定按 `Dataset.created_at` 倒序展示，没有搜索、排序选择或移除入口。
- 评测任务列表当前支持状态和数据集过滤，固定按 `EvaluationJob.created_at` 倒序展示。
- `EvaluationJob.dataset_id` 以外键引用数据集；直接删除数据集记录会破坏历史任务关联。
- 报告、下载、重试、取消和 Worker 状态机依赖评测任务原始 `state`，不能把任务状态改成 `ARCHIVED`。
- 项目没有列级数据库迁移框架，但应用启动时会通过 SQLAlchemy `create_all` 创建缺失的新表。
- 归档必须是元数据操作，不移动或删除数据集目录、附件、评测输出和报告文件。

## 3. 方案选择

### 3.1 数据集

复用现有 `Dataset.status`：归档时设置为 `ARCHIVED`，并在 `inspection_json` 中保存归档前状态、归档时间和操作用户。恢复时严格验证归档元数据并还原原状态。

这一方案不需要修改现有表结构，也能让所有既有“仅 READY 可评测”校验自然拒绝归档数据集。

### 3.2 评测任务

新增 `EvaluationJobArchive` 表，为每个已归档任务保存一条独立记录：

- `evaluation_job_id`：表的主键和外键，指向 `evaluation_jobs.id`；
- `archived_at`：UTC 归档时间；
- `archived_by`：可空用户外键，记录操作用户。

任务的 `state`、`stage`、参数、输出目录和报告证据不变。归档查询通过该表的存在性判断，恢复时删除对应归档记录。新表由现有初始化流程创建，不对旧表执行 `ALTER TABLE`。

不采用把归档信息写入 `params_json` 的方案，因为这会把界面生命周期状态混入可复现的运行参数；也不新增旧表的 `archived_at` 列，以避免引入临时数据库迁移机制。

## 4. 归档与恢复规则

### 4.1 数据集归档

- 使用 POST 端点和 CSRF 校验。
- 归档前锁定并重新读取数据集，拒绝不存在、已归档或元数据冲突的记录。
- 检查该数据集不存在 `QUEUED`、`RUNNING` 等活动评测任务；存在时返回 409。
- 将原 `status`、UTC 归档时间和操作用户写入 `inspection_json["_archive"]`，字段固定为 `previous_status`、`archived_at` 和 `archived_by`，避免覆盖现有预检错误。
- 设置 `status = ARCHIVED`。
- 不修改 `path`，不访问或移动数据集目录。

### 4.2 数据集恢复

- 使用 POST 端点和 CSRF 校验。
- 只允许恢复 `status = ARCHIVED` 且归档元数据完整的记录。
- 原状态只能是当前应用会持久化的 `READY` 或 `PREFLIGHT_FAILED`，不能从客户端提交。
- 还原原状态并移除归档元数据；其他 `inspection_json` 内容保持不变。
- 重复恢复或元数据损坏返回 409。

### 4.3 评测任务归档

- 只允许归档 `SUCCEEDED`、`FAILED`、`CANCELLED`、`INTERRUPTED`。
- `QUEUED`、`RUNNING` 或其他非终态返回 409，提示先等待完成或取消任务。
- 在事务中插入唯一的 `EvaluationJobArchive`；重复归档返回 409。
- 不修改任务状态，因此成功任务报告和下载继续可用，失败或中断任务仍保留原始错误与重试语义。

### 4.4 评测任务恢复

- 使用 POST 端点和 CSRF 校验。
- 在事务中删除对应归档记录；不存在归档记录时返回 409。
- 不修改任务本身。

## 5. 查询接口

两个列表继续使用 GET 查询参数，刷新和复制 URL 后保留条件。严格拒绝重复、未知或非法参数。

### 5.1 公共参数

- `q`：可选关键词；去除首尾空白后为空等同未搜索，最大长度为 200 个 Unicode 字符。
- `sort`：枚举值，默认最新；支持 `newest`、`oldest`、`name_asc`、`name_desc`。
- `archived`：缺省为不显示归档；明确值 `1` 时包含普通和归档记录。

关键词采用数据库端不区分大小写的包含匹配。用户输入中的 `%`、`_` 和转义字符按字面量处理，不能扩大匹配范围。

### 5.2 数据集列表

- 关键词匹配 `Dataset.name` 和 `Dataset.path`。
- 默认条件排除 `Dataset.status == ARCHIVED`。
- 时间排序按 `created_at`，名称排序按 `lower(name)` 后再按原始 `name`；所有排序增加 `created_at` 和 `id` 次级键，保证稳定结果。

### 5.3 评测任务列表

- 关键词匹配关联的 `Dataset.name`、`EvaluationJob.profile_name` 和部分任务 ID。
- 保留现有 `state` 与 `dataset_id` 条件，并可与新参数组合。
- 默认使用 `NOT EXISTS` 排除有归档记录的任务；`archived=1` 时不排除。
- 名称排序按关联数据集的 `lower(name)` 和原始 `name`，同名时按任务创建时间和 ID 稳定排序。

## 6. 页面设计

数据集与评测任务列表在标题下使用一致的紧凑工具栏：

- 关键词输入框；
- 排序下拉框；
- “显示已归档”复选框；
- “筛选”按钮；
- 有活动条件时显示“清除”入口；
- 评测任务页继续显示状态筛选。

工具栏使用标准 GET 表单，不依赖 JavaScript即可工作。桌面端横向排列，窄屏下按现有 720px 断点纵向堆叠，不与表格或主操作按钮重叠。

列表行和详情页均提供归档或恢复操作：

- 普通数据集显示“归档”；归档数据集显示“已归档”标记和“恢复”。
- 终态普通任务显示“归档”；归档任务显示“已归档”标记和“恢复”。
- 活动任务不显示可执行归档按钮。
- 归档前通过浏览器原生确认框说明“只从默认列表隐藏，不删除文件、任务或报告”。
- POST 表单携带当前列表的安全返回参数；服务端只允许站内列表或详情目标，防止开放重定向。
- 操作后返回原页面并保留搜索、排序、状态、数据集和归档开关。

归档数据集详情页保留路径、预检、附件和历史评测，只禁用新评测入口。归档评测任务详情和成功报告页面继续可访问。

## 7. 错误处理与安全

- 未登录请求沿用现有登录重定向。
- 找不到实体返回 404。
- CSRF 无效、重复表单字段、未知字段或非法返回目标拒绝处理。
- 非法或重复查询参数返回 422。
- 活动任务或存在活动评测的数据集归档返回 409。
- 重复归档、重复恢复、损坏的数据集归档元数据返回 409。
- 数据库唯一约束作为并发重复归档的最后防线；完整性错误转成受控 409，不暴露 SQL 或内部路径。
- 归档与恢复不执行文件删除、移动、重命名或覆盖。

## 8. 测试与验收

### 8.1 自动化测试

- 数据集名称与路径包含搜索、大小写、空关键词、最大长度和通配符字面量。
- 评测任务按数据集名称、配置名称和部分 ID 搜索。
- 两个列表的四种排序和稳定次级排序。
- 评测任务状态、数据集、关键词、排序和归档开关组合。
- 默认隐藏归档记录，`archived=1` 同时显示普通和归档记录。
- 数据集归档与恢复、活动任务冲突、CSRF、重复操作和元数据损坏。
- 任务终态归档与恢复、活动状态拒绝、并发唯一性。
- 归档前后数据集目录、附件和报告文件内容不变。
- 归档成功任务后，报告页与全部下载入口保持可用。
- 已归档数据集不能创建新评测，也不能重试失败任务；恢复后按原状态恢复能力。
- 桌面与移动视口下工具栏、表格、归档标记和操作按钮无横向页面溢出或重叠。
