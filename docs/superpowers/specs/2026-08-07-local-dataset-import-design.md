# 受控本机数据集导入设计

## 目标

在保留现有 SSH 远程导入的同时，允许管理员从运行 Web 服务和导入 Worker 的机器上选择已配置的本机数据目录，并将数据安全复制到受信任的 `inbox`。本功能不接受任意绝对路径，也不把浏览器所在电脑的目录误认为服务器目录。

## 用户场景

本地单机部署时，数据已经位于服务机器的 `/Users/xueyg/Downloads/fangdianlang_data`。管理员在“新建导入”页面选择本机来源和白名单根目录，填写 `fangdianlang_good_only_ee` 作为相对路径。后台完成复制、校验和登记，最终在数据集页面显示 `READY`。

部署到 4090 后，同一功能中的“本机”指 4090 可见的目录。Mac 浏览器中的 `/Users/...` 不会被 4090 直接读取；这类数据仍需通过 SSH、SMB 挂载或其他同步方式进入 4090 可见的白名单目录。

## 方案比较

### 方案 A：白名单目录复制到 inbox（采用）

- 管理员在配置中登记本机来源及允许的根目录。
- 用户只能选择来源、选择一个精确配置的根目录并填写相对路径。
- Worker 将目录复制到 `staging`，执行现有完整性检查和数据集预检，再原子发布到 `inbox`。
- 优点是数据版本固定、评测性能稳定、现有信任边界和恢复流程可以复用。
- 代价是需要额外磁盘空间和一次本机复制。

### 方案 B：原地登记

- 数据不复制，数据库直接引用来源目录。
- 节省磁盘，但来源可能被修改、移动或卸载；分布式 Worker 也未必能看到相同路径。
- 与当前“评测数据必须位于 inbox”的约束冲突，因此不采用。

### 方案 C：浏览器目录上传

- 从访问网页的电脑上传整个目录。
- 能覆盖客户端和服务器不在同一台机器的情况，但 3.5 GB 以上数据需要分片、断点续传、配额和浏览器恢复协议。
- 与当前服务器本机数据场景不匹配，留作独立功能，不纳入本次范围。

## 配置模型

`AppConfig` 新增只读的 `local_sources` 映射。每个 `LocalSource` 包含唯一名称和一个或多个绝对根目录：

```yaml
local_sources:
  this-mac:
    roots:
      - /Users/xueyg/Downloads/fangdianlang_data
```

规则如下：

- 本机来源名和 SSH 来源名不得重名。
- 根目录必须是规范化绝对路径，不允许 `..`、控制字符、尾随分隔符或重复分隔符。
- 配置解析不要求可移动磁盘始终在线；创建任务和 Worker 执行时再验证目录存在、可读且没有符号链接逃逸。
- `local_sources` 为空时，现有 SSH 行为保持不变。

## 页面与请求

“新建导入”页面将“远程源”改为“数据来源”，用分组选项区分“本机目录”和“远程 SSH”。根目录选项绑定所属来源，切换来源时只显示对应根目录。相对路径仍必须是不以 `/` 开头的规范化路径，数据集名称沿用现有字符和长度规则。

POST `/imports` 保持现有字段：

- `source_name`
- `root`
- `relative_path`
- `target_name`

路由通过配置判断来源属于本机还是 SSH。两个来源集合中不存在该名称、根目录不属于该来源、相对路径非法或目标名称非法时，在创建数据库记录和入队之前返回 422。

本次不增加任意绝对路径输入框，也不增加浏览器文件上传控件。

## 持久化兼容

不修改 `ImportJob` 表结构：

- `source_name` 保存配置中的来源名。
- `remote_root` 作为兼容字段保存本次来源根目录。
- `remote_path` 作为兼容字段保存相对路径。

本机来源和 SSH 来源名称必须全局唯一，因此 Worker 可以根据当前配置可靠确定传输类型。已有远程任务无需迁移。

## Worker 数据流

```text
QUEUED
  -> CONNECTING（本机来源在页面显示为“准备”）
  -> TRANSFERRING
  -> VERIFYING
  -> PREFLIGHT
  -> READY
```

`run_import_task` 根据 `source_name` 选择传输适配器：

- SSH 来源：继续使用现有 SSH 固定主机密钥和 rsync 参数。
- 本机来源：验证根目录与相对路径，构造不经过 shell 的本机 rsync 参数，将来源目录内容复制到该任务专属的 `staging`。

两种适配器之后共用现有逻辑：

1. 目标名称不得已存在。
2. `staging` 与 `inbox` 必须位于同一文件系统。
3. 传输结果不得为空。
4. `inspect_dataset()` 必须返回 `ready=True`。
5. 发布前再次验证目录和目标边界。
6. 使用不覆盖已有目标的原子重命名进入 `inbox`。
7. 保存数据指纹、大小、格式和 Episode 数量，并将任务标记为 `READY`。

本机导入继续使用 transfer 队列，因此复制 3.5 GB 数据不会阻塞 Web 请求。复制和预检由 transfer Worker 所在机器执行；后续抽帧和指标计算由 evaluations Worker 所在机器执行。

## 本机路径安全

- 只接受配置中精确登记的根目录。
- 相对路径复用严格规范化规则，拒绝绝对路径、空段、`.`、`..`、反斜杠和控制字符。
- Worker 从已登记根目录逐层解析来源目录，拒绝来源路径中的符号链接和非目录组件，并确认解析结果仍位于根目录内。
- rsync 使用参数数组并设置 `shell=False`，来源路径不会进入 shell 命令字符串。
- 复制后的 `staging` 仍由现有扫描器拒绝符号链接、特殊文件、损坏 Parquet 和缺失视频引用。
- 所有错误消息继续限制长度并清除敏感路径参数，不向页面回显凭据。

## 失败与恢复

- 根目录未挂载、来源不存在、无读取权限或路径逃逸：任务进入 `FAILED`，不会创建 Dataset。
- 复制中断：保留任务专属 `staging`，重试时继续使用 rsync 的部分传输能力。
- 预检失败：保持现有错误摘要和失败状态，不发布到 `inbox`。
- 目标名称冲突：在复制前失败，不覆盖已有数据集。
- 发布后数据库提交异常：沿用现有发布回滚和中断任务对账逻辑。

## 测试范围

自动化测试覆盖：

- 配置接受合法本机根目录，拒绝不规范路径和本机/SSH 来源重名。
- 新建导入页面同时显示本机和 SSH 来源，并正确关联根目录。
- 本机来源表单可以创建任务并入队；伪造来源、根目录和路径在入队前被拒绝。
- 本机路径解析拒绝绝对路径、遍历、符号链接逃逸和缺失目录。
- 本机传输使用 argv、不会调用 shell，并能报告单调进度与响应取消。
- 本机任务复用 `staging → preflight → inbox` 流程，成功登记 READY 数据集。
- 本机预检失败、目标冲突和传输失败不会留下错误的 READY 记录。
- 现有 SSH 导入、数据集扫描和评测工作流保持通过。

真实验收使用 `/Users/xueyg/Downloads/fangdianlang_data/fangdianlang_good_only_ee`：页面提交后观察任务完成，确认数据集类型为 `lerobot`、Episode 数为 199、状态为 `READY`，再提交一次最小评测验证 Worker 能读取发布后的目录。

## 非目标

- 不允许任意服务器绝对路径。
- 不从浏览器上传整个目录。
- 不原地登记 Downloads、SMB 或 NAS 数据。
- 不自动删除原始来源目录。
- 不改变指标计算或 VLM API 执行位置。
