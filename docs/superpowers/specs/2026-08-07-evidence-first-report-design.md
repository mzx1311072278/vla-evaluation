# 证据优先的完整评测报告设计

## 目标

让 Web 报告覆盖原始发版报告中对当前任务有真实数据来源的关键内容，同时保证每个展示值都能追溯到当前任务的数据库记录、数据集元信息、版本化配置或已落盘评测产物。旧报告中的 13 Episode 数值、外部模型默认参数和人工发版判断不得进入当前任务结果。

## 分支与范围

- 实现分支：`feature/vla-eval-web-vlm-api-backend`。
- 保留当前报告 URL、筛选功能、任务/数据集入口、平滑度 SVG 预览和下载功能。
- 扩充报告读取模型、指标定义、页面章节和自动化验收。
- 不新增数据库表，不在打开报告时重新执行评测或计算新指标，不引入外部公式渲染 CDN。

## 数据真实性原则

报告字段只允许来自以下四类来源：

1. `EvaluationJob`、`Dataset` 及提交时固化的 `provenance_json`。
2. `load_session(dataset.path)` 和 `load_episodes(dataset.path, session)` 返回的数据集事实。
3. `load_metrics_core(output_dir, session)`、`load_episode_metrics(output_dir, session)` 和可选 `attempt_eval/attempt_summary.json` 返回的评测结果。
4. 与计算代码同仓、版本化的指标定义。

没有以上来源的字段进入“证据缺口”表，不使用旧报告值、外部默认值或从名称推断出的结论。配置了 VLM 不等于执行了 VLM；只有实际 attempt summary 存在且有效时才显示 VLM 结果。

## 报告结构与优先级

### 1. 首屏结果摘要

按决策重要性展示：GSR、成功/失败数、成功 TTS、平滑度、待人工复核数。紧随其后显示一段事实性摘要，包括 Episode 总量、可用平滑度覆盖数和 VLM 是否实际执行。

发版判断独立显示为“未配置自动发版判定”。系统没有版本化 release-gate 或审批记录时，不生成“准许发版”或“暂缓发版”。

### 2. 评测配置与任务边界

使用表格展示任务文本、数据集、评测 profile/version、rollout mode、FPS、数据后端、创建时间、应用版本和 Git SHA。VLM 配置表明确区分“已配置”和“本次已执行”。

### 3. 来源与数据质量

来源表逐项列出核心指标、Episode 指标、数据集元信息、VLM 结果和报告文件的真实接口或产物路径及状态。

数据质量表展示可验证的 Episode 总量、成功/失败、操作员介入 Episode、短时长成功、平滑度有效/缺失数量和预检错误。数据质量只做确定性分类，不生成未经配置的风险等级。

### 4. 指标定义与公式

新增共享的结构化指标定义模块，记录指标名称、用途、方向、计算口径、符号和公式组成。Markdown 报告和 Web 报告从同一模块读取 GSR、TTS、平滑度定义，避免公式文本与实现漂移。

Web 使用语义化 HTML 结构渲染公式，包括变量、上下标、上标和分数布局。公式包含：

- `GSR = N_success / N_total`
- `TTS = mean(duration_s)`，仅统计成功 Episode
- `S = log10(E + 1)`
- `E = sum(||j_k||^2) * delta_t`
- `j_k = (x_k - 3x_(k-1) + 3x_(k-2) - x_(k-3)) / delta_t^3`

公式定义同时标注平滑度过滤非有限帧、介入帧、时间排序和有效帧不足时跳过的实际实现规则。

### 5. Episode、失败与 VLM 明细

Episode 表保留筛选并补齐结果、时长、综合/左右平滑度、坐标空间、有效帧、介入、备注和跳过原因。失败案例通过结果和备注形成表格，不生成不存在的失败分类。

当 VLM 真实执行时，追加置信度、尝试次数、失败尝试、复核状态、原因和证据定位；未执行时只显示说明，不显示空的 VLM 结论列。

### 6. 组件、覆盖范围与证据缺口

组件表展示 profile adapter/plugin/image key、实际产物和能够从数据 schema 验证的输入/动作信息。

模型架构、实际训练超参、checkpoint、部署 PyTorch/CUDA/cuDNN、GPU/工控机、标定/力传感器、OOD/鲁棒/安全测试、release-gate 和审批记录没有当前接口，统一放入证据缺口表。每行说明缺少什么、对报告有什么影响、未来应由哪个类型的接口补齐。

### 7. 结果文件

保留当前下载表和认证要求。下载目录支持 profile 中定义的根级产物及真实嵌套路径 `attempt_eval/attempt_summary.json`、`attempt_eval/attempt_summary.csv`。

新任务在提交 provenance 中固化 output contract，供历史报告准确回放。旧任务没有该快照时，只依据受支持的固定产物清单和实际存在文件展示下载，不把当前 profile 文件当作历史事实。

## 模块边界

### 共享指标定义

在 `Genie02_report` 下提供不依赖 Web 的指标定义模块。它只描述当前计算口径，不读取文件、不执行计算。`genie02_markdown_report.py` 和 Web 视图模型都是消费者。

### 报告视图模型

新增 Web 报告视图构建模块，负责调用现有严格加载器、关联 session/Episode/metrics/VLM/provenance，并返回模板所需的结构化数据。路由只负责鉴权、加载数据库对象、解析筛选和返回响应，避免继续堆积报告业务逻辑。

### 下载解析

下载使用规范化 POSIX 相对路径作为 ID。解析后必须严格位于 job `output_dir` 内，且匹配允许的根级文件或 `attempt_eval/` 文件。符号链接、目录穿越、绝对路径、未知文件继续返回 404。

## 数据流

1. 路由读取 `EvaluationJob` 和 `Dataset`，确认任务存在输出目录。
2. 视图构建器严格读取 dataset session、原始 Episode、核心指标和 Episode 指标。
3. 构建器读取并校验可选 VLM summary，组合逐 Episode 行。
4. 构建器根据 provenance、数据集 inspection 和实际产物形成配置、来源、质量、缺口和下载表。
5. 模板只负责转义和展示，不计算指标、不解析 JSON/CSV、不推断结论。

## 错误处理

- 必需的 session 或核心指标无效：报告返回 404，避免展示部分错误结果。
- 可选 VLM 产物缺失：明确显示“本次未执行或无有效产物”，主报告继续可用。
- 可选 VLM 产物格式错误：显示证据不可用状态，不把错误内容合并进 Episode。
- 数据集与指标 session ID 不一致：拒绝报告，防止跨任务串数据。
- profile/provenance 字段缺失：显示未记录，不从当前配置或文件名猜测。
- 下载路径不安全或不在允许清单：返回 404。

## 测试策略

按测试先行实现，覆盖以下必要场景：

- 真实 loader 数据进入配置、质量、Episode 和来源表。
- 核心指标及事实摘要使用当前任务值，不出现旧报告数值。
- VLM 已配置但关闭、已启用但无产物、已有有效产物三种状态准确区分。
- 共享公式定义同时被 Markdown 与 Web 使用，公式在 HTML 中有正确的上下标/上标/分数结构。
- 无 release-gate 时只显示“未配置自动发版判定”。
- 证据缺口表不包含伪造值。
- 嵌套 attempt summary 可下载，路径穿越和未知嵌套文件仍被拒绝。
- 现有 Episode 筛选、SVG、任务/数据集导航和根级下载不回归。
- 桌面和移动端页面无横向溢出、文字遮挡或表格破版。

验证顺序为聚焦单元测试、报告 Web 测试、相关回归测试、全量 pytest、Ruff、`git diff --check`，最后使用真实 HTTPS 页面完成桌面/移动端和下载验收。
